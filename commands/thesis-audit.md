# `/thesis-audit` — Auditoria de Pesquisa

## Finalidade

Executar uma auditoria transversal antes de submeter artigo, fechar capítulos, entregar dissertação ou defender claims importantes.

## Escopo

Verifique a cadeia:

`problema → lacuna → contribuição → RQ → método → dados → análise → resultado → inferência → limitação → conclusão`

## Procedimento

1. Leia ledger, protocolo, artefato, riscos e decisões, quando disponíveis.
2. Para cada claim, encontre RQ, evidência, dataset, script/configuração, resultado e limitação.
3. Marque elo ausente como `[EVIDÊNCIA PENDENTE]`.
4. Audite coerência entre introdução, método, resultados, discussão e conclusão.
5. Audite desvios do protocolo.
6. Use rubricas de contribuição, validade, artefato e interpretação.
7. Classifique achados como bloqueante, importante ou editorial.

## Saída obrigatória

| Prioridade | Achado | Evidência | Impacto no claim | Correção mínima | Responsável/decisão |
| --- | --- | --- | --- | --- | --- |
| Bloqueante |  |  |  |  |  |

Depois da tabela: claims suportados, claims inconclusivos/refutados/removidos, gates atendidos/pendentes e até cinco ações de maior retorno.

## Critério de término

Termine quando todos os claims importantes tiverem status explícito e lacunas bloqueantes tiverem ação ou decisão atribuída.
